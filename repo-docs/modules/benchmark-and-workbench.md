# 工作台存档、预览服务与自动对测

除了让游戏正常运转，PVSSPW 的重要工程目标是用同一套输入归档在桌面无头浏览器与移动设备上稳定复现对比实验，同时避免任何商业游戏包、固件或调试端点混入源码仓库及公开网页空间。

## 本地回环安全预览服务与启动接口 (`serve.py`)

静态与本地对测 HTTP 服务器严格把访问边界控制在回环网络内部与指纹白名单之中：
- **强制安全响应头与隔离域**：因为 WebAssembly 多线程与离屏音频工作流高度依赖 `SharedArrayBuffer`，服务为核心页面注入跨源隔离响应头，并固定以独立回环端口区分不同核心（如 Vitaslop 与 Vita3K Web），从浏览器同源策略层面上彻底隔开双方的持久化存储与存档区。
- **严格校验本机边缘启动请求**：`serve.py` 上的后台切换接口仅限启用启动器开关时响应，强校验 `Host`、`Origin` 均为同源本地环回地址、`Sec-Fetch-Site === 'same-origin'` 以及定制头部标识，且负载长度上限严格限制在 256 字节并由 `parse_open_edge_payload` 按硬件预设表格检验，防止任意网页跨域探测本机桌面驱动程序。

对应源码：[本地预览服务](../../scripts/serve.py) 与 [驱动参数规约](../../scripts/edge_backends.py)。

## 指纹锁定的离线快照与样本准备 (`prepare.py`)

为保障不依赖上游服务器、跨时间复测也能对齐到同一二进制核心和同一份测试帧范围，准备脚手架按 SHA-256 摘要执行两阶段解包：
- `players` 模式离线校验并展开随仓归档的 93 个对照播放器文件；
- `inputs` 模式要求操作者传入本机自备压缩归档并核对整包哈希一致，按严格固定顺序与时间戳重建最小本体镜像与对应系统模块归档，剔除无关旧存档与大型追加内容后放入被 Git 忽略的本机缓存目录。

对应源码：[准备脚本](../../scripts/prepare.py)、[核心快照清单](../../bench/players.lock.json) 与 [输入校验指纹](../../bench/sample.lock.json)。

## 存档安全检验、像素级计数与对比制表 (`files.js` / `battle.mjs` / `report.py`)

无论是在玩家桌面手工游玩，还是运行无人值守对测脚本，数据流都在离开或汇入存储前完成结构性防呆校验：

<details>
<summary>对测及存储流程关键契约说明</summary>

1. **恢复存档前的工作线程结构验证**：玩家导入单一游戏或整套全量存档压缩包时，前端把解压后的字节流按名称传给专用检查工作线程；若文件名模式不合规范、出现重名条目或检验线程报错，立即中止并拒绝写入，正式覆盖本地配置前必须经过确认对话框。
2. **战斗场景零干扰像素帧统计**：`battle.mjs` 在固定出生点场景先核验角色受控起跳、落地状态，在切入采样后开启 GPU 逐像素着色器持续运行 600 秒，把全画面变化帧率与屏幕中央区域变化率、表面提交数分开记账，防止黑屏或静帧空提交虚高帧数。
3. **带指纹核验的报告生成 (`report.py`)**：生成对比表时脚本再次计算所有待嵌入图片文件的 SHA-256 摘要，并检查自动多线程试验用的工作线程数量与核心二进制指纹一致，任何截图篡改或输入样本漂移都会引发异常阻断报告生成。

</details>

对应源码：[存档导出与校验](../../web/files.js)、[固定场景运行脚本](../../scripts/battle.mjs) 与 [报告生成器](../../scripts/report.py)。如需追溯上游核心补丁或线程池策略，回到[Vitaslop 补丁栈与自适应线程策略](core-patching-and-smp.md)或[按职责找代码](../code-map.md)。
